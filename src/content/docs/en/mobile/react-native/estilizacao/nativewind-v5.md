## What it is

**NativeWind** lets you style React Native components with Tailwind CSS classes in `className`. In v5, **`react-native-css`** turns the CSS into native styles, and the setup follows **Tailwind v4's CSS-first model**: there is no `tailwind.config.js` anymore, and the theme lives in the CSS itself.

```tsx
<View className="flex-1 items-center justify-center bg-white">
  <Text className="text-xl font-bold text-blue-500">Hello</Text>
</View>
```

## When to use

- When you already know Tailwind and want the same way of styling on web and mobile.
- In new projects that want the latest Tailwind (v4).

## When NOT to use

- In production, if you can't accept a pre-release: v5 is still a **release candidate**, and the docs warn it is "not intended for production use". NativeWind v4 (with Tailwind v3) is the stable one.
- If the project already uses `StyleSheet` or another styling lib everywhere and won't migrate.

## Step by step

### 1. Install NativeWind and react-native-css

The two packages go together and must have **exact, matching versions**. `nativewind@5.0.0-rc.1` requires exactly `react-native-css@3.1.0-rc.1`:

```bash
npm install --save-exact nativewind@5.0.0-rc.1 react-native-css@3.1.0-rc.1
```

### 2. Install the native dependencies

```bash
npx expo install react-native-reanimated react-native-worklets react-native-safe-area-context expo-system-ui
```

`expo install` picks the versions compatible with the SDK. Reanimated and Worklets have native code: Expo Go already includes them, but a development build has to be rebuilt.

### 3. Install Tailwind CSS v4

```bash
npm install --save-dev --save-exact tailwindcss@4.1.12 @tailwindcss/postcss@4.1.12 postcss lightningcss@1.30.1
```

### 4. Pin lightningcss

```json title="package.json"
{
  "overrides": {
    "lightningcss": "1.30.1"
  }
}
```

Run `npm install` again after adding it. Without this override, other dependencies can pull in another `lightningcss` version, and the build fails with deserialization errors involving `global.css`. Check with `npm ls lightningcss`: every entry should show `1.30.1`.

### 5. Configure PostCSS

```js title="postcss.config.mjs"
export default {
  plugins: {
    "@tailwindcss/postcss": {},
  },
};
```

Expo finds `postcss.config.js` and `postcss.config.mjs`, but **not** `.cjs`.

### 6. Create `global.css`

```css title="src/global.css"
@import "tailwindcss/theme.css" layer(theme);
@import "tailwindcss/preflight.css" layer(base);
@import "tailwindcss/utilities.css";

@import "nativewind/theme";
```

The imports are split by layer on purpose. A single `@import "tailwindcss"` can leave the utilities below React Native Web's default styles in the cascade, and the classes stop working on web.

### 7. Configure Metro

If the project doesn't have a `metro.config.js` yet, create one with `npx expo customize metro.config.js` and wrap the default config:

```js title="metro.config.js"
const { getDefaultConfig } = require("expo/metro-config");
const { withNativewind } = require("nativewind/metro");

/** @type {import('expo/metro-config').MetroConfig} */
const config = getDefaultConfig(__dirname);

module.exports = withNativewind(config);
```

### 8. Import the CSS in the root layout

```tsx title="src/app/_layout.tsx" ins={1}
import "@/global.css";

import { Stack } from "expo-router";

export default function RootLayout() {
  return <Stack />;
}
```

Import it **only once**, in the top-most component of the app (with Expo Router, `app/_layout.tsx`). Don't import it in the file that calls `AppRegistry.registerComponent`, or Fast Refresh stops working properly.

### 9. TypeScript types

```ts title="nativewind-env.d.ts"
/// <reference types="react-native-css/types" />

// NOTE: This file should not be edited and should be committed with your source code. It is generated by react-native-css. If you need to move or disable this file, please see the documentation.
```

This is what makes React Native components accept `className`. The file is generated by the lib, so the note stays (it's the exception to the no-comments rule). It must be in the `tsconfig.json` `include`:

```json title="tsconfig.json"
{
  "include": ["**/*.ts", "**/*.tsx", ".expo/types/**/*.ts", "expo-env.d.ts", "nativewind-env.d.ts"]
}
```

`npx expo start --clear` and `npx expo-doctor` create the file and edit `tsconfig.json` on their own if anything is missing.

### 10. Light/dark theme (optional)

To make the app follow the system theme, use `automatic` in `app.json`. To lock a theme, use `light` or `dark`:

```json title="app.json"
{
  "expo": {
    "userInterfaceStyle": "automatic"
  }
}
```

Changing native config requires a rebuild in a development build.

## Full example

```tsx title="src/app/index.tsx"
import { Text, View } from "react-native";

export default function Index() {
  return (
    <View className="flex-1 items-center justify-center bg-white">
      <Text className="text-xl font-bold text-blue-500">Welcome to Nativewind!</Text>
    </View>
  );
}
```

If the text shows up centered, blue and bold on a white background, it's working. Run `npx expo start --clear` the first time to clear Metro's cache.

## Common pitfalls

- **Mismatched versions** of `nativewind` and `react-native-css`: install both with `--save-exact` and with the pair the peer dependency asks for (`npm view nativewind@<version> peerDependencies`).
- **Forgetting the `lightningcss` override**: shows up as a deserialization error involving `global.css`.
- **`postcss.config.cjs`**: Expo doesn't find it. Use `.mjs` or `.js`.
- **Stale Metro cache** after installing: classes don't apply until you run with `--clear`.
- **Type file name**: don't use `nativewind.d.ts` or a name that matches another file, folder or `node_modules` package, because TypeScript ignores the reference.
- **`.css` import error in TypeScript**: add `declare module "*.css";` to a declaration file included in `tsconfig`.

## What changed between versions

- **v4 → v5**:
  - Tailwind v3 → Tailwind v4. `tailwind.config.js` with `presets: [require("nativewind/preset")]` goes away; the theme is defined in CSS.
  - The Babel preset goes away (`nativewind/babel` and `jsxImportSource: "nativewind"`). `babel-preset-expo` stays as is.
  - PostCSS comes in (`postcss.config.mjs` with `@tailwindcss/postcss`).
  - `global.css` swaps `@tailwind base/components/utilities` for layered `@import`s plus `nativewind/theme`.
  - `withNativeWind(config, { input: './global.css' })` becomes `withNativewind(config)`, with no `input`.
  - Types move from `nativewind/types` to `react-native-css/types`.
- **rc.0 → rc.1**: the docs still pin the `rc.0` pair. The `rc.1` pair worked on Expo SDK 58 with no config changes.
