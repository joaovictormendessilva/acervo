## O que é

O **NativeWind** permite estilizar componentes do React Native com classes do Tailwind CSS no `className`. Na v5, quem transforma o CSS em estilos nativos é o **`react-native-css`**, e a configuração segue o modelo **CSS-first do Tailwind v4**: não existe mais `tailwind.config.js`, e o tema fica no próprio CSS.

```tsx
<View className="flex-1 items-center justify-center bg-white">
  <Text className="text-xl font-bold text-blue-500">Olá</Text>
</View>
```

## Quando usar

- Quando você já conhece Tailwind e quer a mesma forma de estilizar no web e no mobile.
- Em projetos novos que querem a versão mais recente do Tailwind (v4).

## Quando NÃO usar

- Em produção, se você não aceita um pré-release: a v5 ainda é **release candidate**, e a doc avisa "not intended for production use". A v4 do NativeWind (com Tailwind v3) é a estável.
- Se o projeto já usa `StyleSheet` ou outra lib de estilo em todo lugar e não vai migrar.

## Passo a passo

### 1. Instalar o NativeWind e o react-native-css

Os dois pacotes andam juntos e devem ter **versões exatas e casadas**. O `nativewind@5.0.0-rc.1` exige exatamente `react-native-css@3.1.0-rc.1`:

```bash
npm install --save-exact nativewind@5.0.0-rc.1 react-native-css@3.1.0-rc.1
```

### 2. Instalar as dependências nativas

```bash
npx expo install react-native-reanimated react-native-worklets react-native-safe-area-context expo-system-ui
```

O `expo install` escolhe as versões compatíveis com o SDK. O Reanimated e o Worklets têm código nativo: o Expo Go já os inclui, mas um development build precisa ser refeito.

### 3. Instalar o Tailwind CSS v4

```bash
npm install --save-dev --save-exact tailwindcss@4.1.12 @tailwindcss/postcss@4.1.12 postcss lightningcss@1.30.1
```

### 4. Fixar o lightningcss

```json title="package.json"
{
  "overrides": {
    "lightningcss": "1.30.1"
  }
}
```

Rode `npm install` de novo depois de adicionar. Sem esse override, outras dependências podem trazer outra versão do `lightningcss`, e o build quebra com erros de deserialização do `global.css`. Confira com `npm ls lightningcss`: todas as entradas devem mostrar `1.30.1`.

### 5. Configurar o PostCSS

```js title="postcss.config.mjs"
export default {
  plugins: {
    "@tailwindcss/postcss": {},
  },
};
```

O Expo encontra `postcss.config.js` e `postcss.config.mjs`, mas **não** `.cjs`.

### 6. Criar o `global.css`

```css title="src/global.css"
@import "tailwindcss/theme.css" layer(theme);
@import "tailwindcss/preflight.css" layer(base);
@import "tailwindcss/utilities.css";

@import "nativewind/theme";
```

Os imports ficam separados por layer de propósito. Um `@import "tailwindcss"` único pode deixar as utilities abaixo dos estilos padrão do React Native Web na cascata, e as classes deixam de funcionar na web.

### 7. Configurar o Metro

Se o projeto ainda não tem `metro.config.js`, crie com `npx expo customize metro.config.js` e envolva a config padrão:

```js title="metro.config.js"
const { getDefaultConfig } = require("expo/metro-config");
const { withNativewind } = require("nativewind/metro");

/** @type {import('expo/metro-config').MetroConfig} */
const config = getDefaultConfig(__dirname);

module.exports = withNativewind(config);
```

### 8. Importar o CSS no layout raiz

```tsx title="src/app/_layout.tsx" ins={1}
import "@/global.css";

import { Stack } from "expo-router";

export default function RootLayout() {
  return <Stack />;
}
```

Importe **uma vez só**, no componente mais alto do app (com Expo Router, o `app/_layout.tsx`). Não importe no arquivo que chama `AppRegistry.registerComponent`, porque o Fast Refresh para de funcionar direito.

### 9. Tipos do TypeScript

```ts title="nativewind-env.d.ts"
/// <reference types="react-native-css/types" />

// NOTE: This file should not be edited and should be committed with your source code. It is generated by react-native-css. If you need to move or disable this file, please see the documentation.
```

É isso que faz o `className` ser aceito nos componentes do React Native. O arquivo é gerado pela lib, por isso a nota fica (é a exceção à regra de não ter comentários). Ele precisa estar no `include` do `tsconfig.json`:

```json title="tsconfig.json"
{
  "include": ["**/*.ts", "**/*.tsx", ".expo/types/**/*.ts", "expo-env.d.ts", "nativewind-env.d.ts"]
}
```

O `npx expo start --clear` e o `npx expo-doctor` criam o arquivo e editam o `tsconfig.json` sozinhos se faltar alguma coisa.

### 10. Tema claro/escuro (opcional)

Para o app seguir o tema do sistema, use `automatic` no `app.json`. Para fixar um tema, use `light` ou `dark`:

```json title="app.json"
{
  "expo": {
    "userInterfaceStyle": "automatic"
  }
}
```

Mudar config nativa exige rebuild num development build.

## Exemplo completo

```tsx title="src/app/index.tsx"
import { Text, View } from "react-native";

export default function Index() {
  return (
    <View className="flex-1 items-center justify-center bg-white">
      <Text className="text-xl font-bold text-blue-500">Welcome to Nativewind!</Text>
    </View>
  );
}
```

Se o texto aparecer centralizado, azul e em negrito sobre fundo branco, está funcionando. Rode com `npx expo start --clear` na primeira vez para limpar o cache do Metro.

## Armadilhas comuns

- **Versões descasadas** de `nativewind` e `react-native-css`: instale as duas com `--save-exact` e com o par que o peer dependency pede (`npm view nativewind@<versão> peerDependencies`).
- **Esquecer o override do `lightningcss`**: aparece como erro de deserialização envolvendo o `global.css`.
- **`postcss.config.cjs`**: o Expo não encontra. Use `.mjs` ou `.js`.
- **Cache antigo do Metro** depois de instalar: as classes não aplicam até rodar com `--clear`.
- **Nome do arquivo de tipos**: não use `nativewind.d.ts` nem um nome igual a outro arquivo, pasta ou pacote do `node_modules`, porque o TypeScript ignora a referência.
- **Erro de import `.css` no TypeScript**: adicione `declare module "*.css";` num arquivo de declaração incluído no `tsconfig`.

## O que mudou entre versões

- **v4 → v5**:
  - Tailwind v3 → Tailwind v4. Sai o `tailwind.config.js` com `presets: [require("nativewind/preset")]`; o tema passa a ser definido no CSS.
  - Sai o preset do Babel (`nativewind/babel` e `jsxImportSource: "nativewind"`). O `babel-preset-expo` fica como está.
  - Entra o PostCSS (`postcss.config.mjs` com `@tailwindcss/postcss`).
  - O `global.css` troca `@tailwind base/components/utilities` pelos `@import` em layers e pelo `nativewind/theme`.
  - O `withNativeWind(config, { input: './global.css' })` vira `withNativewind(config)`, sem `input`.
  - Os tipos passam de `nativewind/types` para `react-native-css/types`.
- **rc.0 → rc.1**: a doc ainda fixa o par `rc.0`. O par `rc.1` funcionou no Expo SDK 58 sem mudanças na configuração.
